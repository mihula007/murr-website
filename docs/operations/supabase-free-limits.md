# Квоты Supabase Free и Resend

Проверено 14.11.2026 по [тарифам Supabase](https://supabase.com/pricing),
[лимитам Edge Functions](https://supabase.com/docs/guides/functions/limits),
[паузе проектов](https://supabase.com/docs/guides/platform/free-project-pausing)
и [тарифам Resend](https://resend.com/pricing). Условия меняются: перед
решениями, зависящими от квот, перепроверять.

Оценки ниже — для клана до 200 участников (порог `MEMBER_LIST_LIMIT` 250)
и не измерены на живых данных. После месяца работы сверить с
Dashboard → Usage и обновить этот файл.

### Вызовы функции — главный риск

Каждое чтение и запись — вызов `api`. Постоянная нагрузка — опросы при
видимой вкладке:

- шапка: `notifications/summary` раз в 60 с — 60 вызовов в час;
- открытая ветка обсуждения: `discussions/changes` раз в 30 с — ещё 120 в час.

Пример: 150 участников держат сайт открытым по часу в день — только
шапка даёт 150 × 60 × 30 ≈ 270 тыс. в месяц; переходы по разделам
(~50 вызовов за визит) — ещё ≈ 225 тыс. Это у самого предела. При
получасе в день — около 250 тыс.

Что делать, если Usage покажет рост к 400 тыс.: увеличить `pollMs` в
`@contracts/notifications` и `@contracts/discussions` (решения Q-58,
Q-66 — менять только с согласия владельца), не опрашивать без фокуса окна.
При превышении квоты Free функции перестают отвечать до конца периода,
то есть сайт перестаёт работать.

## Пауза проекта

Free ставит проект на паузу после 7 дней без достаточной пользовательской
активности базы; предупреждение приходит письмом примерно за неделю.
Данные сохраняются, возобновление — **Resume project** в Dashboard в
течение года. Пока сайт живёт, ежедневные заходы участников держат проект
активным. Документация говорит о пользовательской активности, поэтому
еженедельное задание Cron может не учитываться: на него не рассчитывать. Риск — затишье (например, до
запуска): раз в несколько дней открыть сайт или Dashboard.

## Письма Auth (Resend Free)

| Лимит Resend Free | Значение    |
| ----------------- | ----------- |
| В месяц           | 3 000 писем |
| В день            | 100 писем   |
| Доменов           | 3           |
| Журнал писем      | 30 дней     |

Письма — только коды регистрации и сброса пароля, десятки в месяц.
Supabase Auth со своим SMTP дополнительно ограничивает отправку
(по умолчанию 30 писем в час на проект) и не чаще одного письма в 60 с на
адрес (`max_frequency`). Массовая регистрация в один вечер может упереться
в 30 в час — тогда поднять `auth.rate_limit.email_sent` в
`[remotes.production]`.

## Доступ из России

Сайт на GitHub Pages, API — домен `*.supabase.co`. Были сообщения о
блокировке адресов Supabase у части российских провайдеров; на 14.11.2026
не проверено. Проверить открытием
`https://fbhndmsmusbqntdymnaz.supabase.co/functions/v1/api/catalog/classes`
из российской сети без VPN у нескольких провайдеров. Собственный домен
API в Supabase платный (запрещено ограничением Free); при блокировке нужен
бесплатный прокси — решение владельца.
