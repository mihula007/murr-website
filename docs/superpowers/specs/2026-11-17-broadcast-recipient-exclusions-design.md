# Исключение участников из одной рассылки

## Намерение

Офицеры и администраторы должны иметь возможность не отправлять конкретное объявление одному или нескольким участникам, которым оно обычно пришло бы. Исключение действует только для этого объявления.

## Цели

- Перед отправкой показать подходящих получателей для выбранных каналов и текущего вида объявления.
- Изначально оставить отмеченными всех подходящих получателей.
- Снятие отметки исключает человека из всех выбранных каналов для текущего объявления.
- Пересчитывать число получателей отдельно для каждого канала.
- Поддержать список больше 50 человек через поиск и курсорную подгрузку; на телефоне показывать карточки без горизонтальной прокрутки.
- Передавать исключения при отправке и учитывать их в серверных числах и фактической доставке.
- В записи журнала отправки хранить общее число уникальных исключённых, не их ники.

## Не входит

- Постоянный отказ человека от рассылок.
- Исключения в черновиках или шаблонах; они существуют только в открытой форме до её очистки или ухода.
- Изменение состава доступных каналов и существующих правил: участники внутреннего состава с активной привязкой, ограничения анонса группы участниками группы и исключение уже ответивших для анонса события.
- Уведомление человека о том, что его исключили.
- Отдельная запись журнала при отметке/снятии отметки; журналируется отправка, как и сейчас.

## Ограничения

- Интерфейс и тексты — на русском.
- Изменение должно остаться в текущей архитектуре: React/Vite, TanStack Query, одна Edge Function Supabase, общие Zod-контракты и существующие реализации каналов.
- Большой список использует серверный поиск и курсорную пагинацию; чтение идёт через функцию `api`.
- Изменения совместимы с уже опубликованным клиентом; новое поле запроса отправки необязательное.
- Существующие черновики, шаблоны и данные участников не меняются.

## Подходы

1. **Исключать людей для текущего объявления — выбранный подход.** В форме показывается список подходящих получателей; снятая отметка исключает человека из всех выбранных каналов. Временное правило понятно, обратимо до отправки и не меняет настройки участника.
2. **Постоянно отключать рассылки для участника.** Это затронуло бы все будущие объявления и потребовало бы отдельного управления настройкой; не соответствует выбранному сопровождающим поведению.

## Утверждённое поведение

- Действие доступно на странице «Рассылка» офицерам и администраторам.
- Список показывает уникальных людей, которые могут получить сообщение хотя бы в одном выбранном канале. Сервер учитывает текущий источник объявления, активность привязки, внутреннюю роль, блокировку бота, удаление аккаунта и правила события/группы.
- Поиск выполняется по нику на сервере; при большом составе список загружается курсорными страницами. Один человек появляется один раз, даже если подключено несколько выбранных каналов.
- Все получатели изначально отмечены. Снятая отметка хранится в текущей форме и означает «не посылать ни в один выбранный канал».
- Числа подтверждения отдельно для каждого канала учитывают исключённых. Если после исключений не остаётся ни одного получателя во всех выбранных каналах, отправка запрещена тем же пояснением о пустой аудитории/всех ответивших, которое соответствует существующему виду рассылки.
- Закрытие подтверждения отправки оставляет форму и выбранные исключения без изменений. При успешной отправке форма очищается, как сейчас.
- Исключённые участники не получают это объявление и не получают отдельное сообщение о пропуске.
- Одна существующая запись аудита отправки содержит число уникальных исключённых, но не их идентификаторы или ники.
- Сохранение черновика и применение шаблона не сохраняют список исключений. Имеющиеся черновики и шаблоны остаются как есть.
- На широком экране список — строки с флажками и ником; на узком — карточки. Список не требует горизонтальной прокрутки.

## Эскиз

```text
Кому отправить
[Поиск по нику________________]
[✓] Ник участника       Telegram · MAX
[ ] Ник участника       Telegram
[✓] Ник участника       MAX
Показаны подходящие получатели. Снятая отметка исключает человека из
всех выбранных мессенджеров.

Получателей: Telegram — 12, MAX — 9
[Отправить анонс]
```

## Оставлено исполнителю

- Подобрать точное расположение списка в форме так, чтобы оно соответствовало текущему порядку «текст → каналы → отправка».
- При изменении выбранных каналов сохранить отмеченные ID в текущей форме; повторно вычислять подходящих получателей и числа по новым каналам.
- Отправка повторно проверяет доступность события/группы и получателей. Сервер применяет исключения по постоянному ID профиля, не по нику, и только к фактически подходящим получателям каждого канала.
- Ники не включать в журнал; число исключённых считать по уникальным профилям, а числа доставки — отдельно по каждому каналу.
