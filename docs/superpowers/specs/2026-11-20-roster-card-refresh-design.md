# Дизайн: оформление карточек и неограниченный состав

Статус: утверждено сопровождающим 20.11.2026.

## Цель

Сделать карточки вкладки «Состав → Участники» похожими на приложенный тёмный фэнтези-концепт, используя обновлённые живописные фоны архива, и позволить списку расти без заданного предела.

## Подходы

1. Перенести демо-страницу архива целиком: отклонено, потому что она содержит фиксированные примеры и пустые слоты, а сайт хранит живой состав.
2. Перенести только оформление и фоны в страницу состава, оставив данные сайта: выбранный подход, сохраняет права, данные и действия существующего сайта.
3. Создать отдельную галерею: отклонено, потому что она дублирует страницу состава.

## Дизайн и поведение

- Из архива используются только локальные фоновые WebP: по одному первому варианту `v1` для каждого из 17 классов. Фон определяется только классом и одинаков у всех участников этого класса — не зависит от ника, роли, ID или позиции. Это сохраняет равное визуальное отношение к участникам.
- Аватар, ник, класс, роль и пять показателей поступают из данных сайта. Профильный аватар сохраняется; при его отсутствии отображается текущая буквенная заглушка. Демо-персонажи, резервные слоты и значения из JSON архива не показываются.
- Карточка сохраняет имя, класс, роль, меню разрешённых действий, ПА/ПЗ/БУ/ХП/БД, тире для пустых значений и подсветку текущего пользователя. Иконки класса в индивидуальной карточке не появляются.
- Сетка: три колонки на широком компьютере, две на планшете, одна на телефоне. На компьютере область списка прокручивается отдельно от страницы; на телефоне список идёт в обычном потоке страницы.
- Вкладка поддерживает любое число участников. Операция `roster/page` отдаёт по 24 записи по курсору `(game_nickname, id)`. Поиск по нику и названию класса и фильтр класса применяются на сервере ко всему составу и сохраняются в адресе страницы. Клиент использует `useInfiniteQuery` и виртуализацию; следующий ответ загружается при приближении к концу доступных карточек.
- Существующая операция `roster/list` остаётся для главной, рейтинга, событий, групп, учёта и других экранов, которым нужно получить состав целиком. Их поведение не меняется.

## Ограничения и безопасность

- React, TypeScript strict, Vite, Tailwind CSS 4 и существующая тема; цвета карточек берутся из токенов, глобальная тема не меняется.
- Backend остаётся одной Supabase Edge Function `api`; новая операция не требует таблицы или миграции. Каждая дополнительная страница загружается отдельным вызовом `api`.
- Просмотр карточек остаётся доступен тем же внутренним ролям. Персональные поля профиля не добавляются в ответы. Данные пользователей, меню, аудит, уведомления и рейтинг не меняются.
- Сборка сайта локальная и автономная; внешние картинки, шрифты и сервисы не добавляются.

## Остаётся разработчику

Реализовать серверную валидацию курсора/поиска/фильтра и стабильную пагинацию; подключить WebP как статические импорты, чтобы Vite корректно упаковал их для GitHub Pages; сохранить адаптивность и доступность клавиатуры; добавить регрессионные тесты новой операции и интерфейса.
