# Правка ника и класса администратором

## Намерение

Администратор должен уметь исправить игровой ник и класс участника прямо в карточке аккаунта, в том числе для своего аккаунта и аккаунтов администраторов. Это закрывает случаи смены персонажа и исправления ошибочных данных.

## Цели и границы

- В карточке есть действие «Изменить профиль» с обязательными полями «Игровой ник» и «Класс», кнопками «Сохранить» и «Отмена».
- Правила значений совпадают с профилем участника: ник до 9 символов, уникальный с учётом регистра; класс выбирается из справочника.
- Сервер проверяет роль администратора, значения и состояние целевого аккаунта; клиентская видимость кнопки не является защитой.
- Карточка передаёт форме текущий идентификатор класса из справочника, не определяя класс по текстовой подписи.
- Одно сохранение применяет оба поля; неизменённые значения не обновляются. Если оба значения прежние, аудит не создаётся.
- Фактическая правка создаёт одну запись в категории «Профили» с перечнем изменённых полей без значений и без уведомления участника.
- Обновляются текущие карточка, таблица аккаунтов, состав и прочие актуальные представления. Исторические снимки закрытых событий и посещений остаются без изменений.
- Пока аккаунт находится в процессе безвозвратного удаления, изменять его нельзя.
- При отмене данные не меняются; незавершённый ввод защищён предупреждением при закрытии карточки или уходе со страницы.

Не входят: редактирование других полей аккаунта, правка списка классов, переписывание истории, новые таблицы, миграции, дополнительные уведомления.

## Подходы

1. **Изменение внутри карточки** — раскрыть форму на месте, затем сохранить или отменить. Выбранный подход: соответствует существующей карточке и не требует перехода в другой экран.
2. **Отдельное окно редактирования** — дополнительный переход и отдельный контекст для двух полей; не подходит, потому что правка тесно связана с открытой карточкой.

## Оставлено реализации

Имена внутренней операции и структуры компонентов следуют существующим модулям `accounts`, `ClassSelect`, TanStack Form и шаблонам записи аудита. Схема базы не меняется.
