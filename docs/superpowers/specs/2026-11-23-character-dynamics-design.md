# Динамика развития участника

## Зачем

Офицерам и другим внутренним ролям нужно видеть, как меняются показатели
персонажа и посещение ивентов, чтобы замечать снижение активности. История
характеристик начинается с запуска наблюдения: прошлые значения из журнала
администратора не изображаются полной историей.

## Цели

- Открывать динамику участника из карточки состава.
- Показывать изменения ПА, ПЗ, БУ, ХП и БД с датами, а посещения закрытых
  ивентов — неделями.
- Давать выбрать один или несколько показателей и период: 30, 90, 365 дней
  или всё время.
- Сохранить текущие характеристики при запуске наблюдения и каждое их
  последующее ручное изменение.
- Показать в заголовке ник, класс, аватар, имя (если заполнено) и дату
  вступления (если известна).
- Оставить интерфейс в тёмной золотистой палитре сайта и удобным на телефоне.

## Не входит

- Историческое восстановление характеристик из записей аудита.
- Новые виды активности помимо посещения ивентов.
- Редактирование характеристик или отметок посещения из окна динамики.
- Изменение обычной карточки состава, рейтинга силы или имеющихся итогов
  закрытых ивентов.

## Варианты решения

1. **Отдельная история значений (выбрано).** При сохранении характеристики
   добавлять запись для каждого изменённого показателя в той же транзакции,
   что обновляет текущий профиль. При запуске функции записать исходные
   текущие значения. Отдельная история надёжна для графиков и не зависит от
   назначения журнала действий.
2. **Строить историю из журнала администратора.** Меньше новых таблиц, но
   журнал предназначен для аудита, может иметь собственные ограничения
   хранения и не является контрактом для временного графика. Не выбрано.

## Доступ и приватность

- Кнопка есть на карточке каждого текущего участника. Состав и динамика
  доступны членам, офицерам, мастеру и администратору; гость, кандидат и
  чтец не получают кнопку или данные от серверной операции.
- В окне динамики текущие имя и дата вступления доступны тем же внутренним
  ролям, что и графики. Имя остаётся скрытым на обычной карточке состава.
- Просмотр не создаёт аудит и уведомления. Изменение характеристики по-прежнему
  может делать только администратор и продолжает записываться в аудит.
- При безвозвратном удалении пользователя история характеристик удаляется
  каскадно; перевод в чтецы историю сохраняет вместе с профилем.

## Поведение

Кнопка «Динамика развития» открывает окно с вкладками «Характеристики» и
«Посещение ивентов». Заголовок содержит данные персонажа; пустое имя не
показывается, неизвестная дата вступления обозначается тире.

На вкладке характеристик можно включить один или несколько рядов ПА, ПЗ, БУ,
ХП и БД. Для выбранных показателей строятся отдельные линейные графики с
собственными шкалами, чтобы разные величины оставались читаемыми. Точка
появляется на исходном снимке или после фактического изменения значения.
Сохранение без изменений не добавляет точек. Очистка значения записывает
пустую точку и создаёт разрыв линии.

На вкладке посещений каждый столбец соответствует календарной неделе по
московскому времени, в которой есть завершённый ивент. Столбец показывает
количество отметок «Посетил», «Не посетил» и «Не отметил» по снимкам закрытых
ивентов. Дата ивента берётся из сохранённого времени начала. Недели без
завершённых ивентов не рисуются. Длинная история не ограничена 50 неделями.

Период выбирается отдельно для графика. Окно можно закрыть кнопкой, клавишей
Escape или обычным способом диалога. Загрузка показывает состояние ожидания;
ошибка даёт возможность повторить запрос; отсутствие точек объясняется
текстом, а не пустой областью. На узком экране фильтры переносятся, графики
идут одной колонкой, окно прокручивается без горизонтальной прокрутки.

## Данные и сохранность

- Новая закрытая для браузерной базы таблица истории хранит профиль, поле,
  значение, время записи и вид точки (исходное значение или изменение).
- Миграция добавляет исходные значения для существующих профилей на момент
  запуска наблюдения; старые события журнала не разбираются.
- `accounts/set-character-stats` и совместимая старая операция записывают
  изменённые поля истории в той же транзакции, что профиль и аудит.
- Серверная операция чтения проверяет внутреннюю роль вызывающего и текущую
  внутреннюю роль выбранного участника. Закрытые значения профиля и источник
  характеристики в ответ не попадают.
- История характеристик и недельные итоги — длинные последовательности; API
  отдаёт их курсорными страницами. Фильтр времени ограничивает выборку, а
  «всё время» позволяет пройти всю историю.
- Посещения считаются из `event_activity_records` только для закрытых ивентов;
  существующие снимки остаются неизменными.

## Визуальное направление

Используются существующие токены темы: тёмные поверхности, золотые рамки и
подписи, основной текст сайта. Графики — спокойные линии и столбцы на фоне
панели, без неоновых градиентов из примеров. Для графиков используется SVG в
React без новой библиотеки.

## Решения сопровождающего

- История начинается с исходных значений на дату запуска и далее пополняется
  при каждом фактическом ручном изменении.
- Просмотр имени в динамике — явное исключение из правила скрытия имени на
  карточке состава; остальные личные данные не раскрываются.
- Можно сравнить несколько показателей одновременно; каждый показан в своей
  панели и со своей шкалой.
- Посещения группируются по неделям; полный выбранный период может включать
  больше 50 недель и точек.
- Дата, недели и фильтрация периодов используют московское время по правилам
  учёта активности.
