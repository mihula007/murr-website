# Вкладка «Подписки» — описание изменения

## Задача

Дать офицерам и администраторам раздела «Рассылка» возможность быстро увидеть, кто из состава привязал Telegram, ВКонтакте или MAX. Это только просмотр статусов; сами привязки остаются под управлением владельцев аккаунтов.

## Поведение

- Вкладка доступна офицеру и администратору. Право проверяется сервером.
- Список включает действующие роли `member`, `officer`, `admin`; кандидаты и чтецы исключены.
- Показываются игровой ник и состояние каждого из трёх каналов. Привязанный канал отмечается фирменной иконкой, остановленная привязка — предупреждением. Непривязанный канал остаётся видимым как приглушённая иконка.
- Если у человека нет ни одной привязки, выделяется вся строка/карточка.
- Список только для чтения; email, имя и прочие поля профиля не возвращаются.
- Поиск по нику выполняется на сервере. Список может быть больше 50: курсорная загрузка и виртуализация; на узком экране строка отображается карточкой.
- Пустой список, отсутствие совпадений, загрузка и ошибка загрузки имеют понятные состояния.
- Новая запись состава или смена роли отражаются при обновлении списка. Данные привязок и существующее управление ими не меняются.

## Внешний вид

На широком экране — список с колонками «Участник», Telegram, ВКонтакте, MAX. На телефоне — карточка с ником и теми же тремя иконками. Предусмотрена текстовая подсказка статусов, чтобы иконки не были единственным доступным обозначением.

## Подходы

1. **Отдельная вкладка в рассылках и отдельное чтение списка на сервере — выбранный подход.** Соответствует месту, названному сопровождающим; права офицера и администратора можно явно проверить сервером. Список сразу возвращает только нужные поля и статусы.
2. **Добавить привязки в управление аккаунтами.** Не подходит: существующий раздел доступен только администратору, а список нужен и офицеру.
3. **Запрашивать статус каждого человека отдельными вызовами.** Не подходит для большого списка: создаёт много запросов и увеличивает нагрузку.

## Ограничения

Использовать существующие стек и компонент иконок мессенджеров; не добавлять библиотек или серверных служб. Список не изменяет, не отвязывает и не рассылает сообщения. Существующие привязки остаются без изменений.
