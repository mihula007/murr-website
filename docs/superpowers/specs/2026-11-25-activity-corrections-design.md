# Ручная корректировка показателей активности

## Цель

Мастер, администратор и офицер с выданным правом могут исправить числовые
показатели посещаемости без изменения закрытой истории событий. Сводка
активности и рейтинг показывают одинаковые счётчики посещений.

## Подходы

- Изменять записи участников в истории закрытых событий — отклонено: сопровождающий выбрал исправление итоговых чисел, история событий должна остаться неизменной.
- Хранить изменения показателей отдельно от событий и применять их к результатам подсчёта — выбрано: исходная история сохраняется, новые события продолжают учитываться автоматически.

## Объём и правила

- В рейтинге доступны счётчики «Посетил», «Не посетил», «Не отметился», пати-лидерство и дни в клане. Все принимают целое неотрицательное итоговое значение; процент недоступен для ручного изменения и рассчитывается автоматически.
- В сводке доступны три счётчика посещений. Они синхронизированы со счётчиками рейтинга; процент рассчитывается автоматически. Если выбран период дат, корректировка сводки отключена, потому что она меняет общий итог.
- У мастера и администратора права есть всегда. В «Мастерке» мастер или администратор назначает офицеру отдельные права на рейтинг и сводку. Для просмотра сводки по-прежнему нужно существующее право просмотра учёта.
- Новые числа сохраняются как постоянные поправки к вычисляемым по закрытым событиям значениям. Закрытие нового события продолжает менять итог обычным образом. Дни в клане продолжают увеличиваться по московской дате.
- Корректировки не меняют строки истории событий, топ-5 на главной или прежние данные без явной правки. Они не создают запись журнала и не отправляют уведомление.
- Кнопка находится в строке таблицы и доступна на карточке строки телефона. Сохранение — по одному участнику, процент показывается только для чтения.

## Ограничения

TypeScript strict, React 19, TanStack Query/Form, zod и Supabase Edge Function `api`; только Supabase Free. Новая таблица и миграция только вперёд. Право проверяется сервером при каждом сохранении. Изменённые данные доступны через те же операции API; клиент Supabase вне разрешённых файлов не используется.

## Проверка

Тесты доказывают хранение поправок, синхронизацию обеих таблиц, автоматический процент, изменение итогов после новых событий, границы нуля, отключение кнопки при фильтре дат и запрет серверного сохранения без права. Ручная проверка включает компьютер и узкий экран телефона.
