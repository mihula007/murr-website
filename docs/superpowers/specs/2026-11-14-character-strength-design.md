# Характеристики персонажей и рейтинг силы

## Зачем

Администратор вручную поддерживает боевые показатели персонажей. Внутренние
участники клана видят эти показатели в составе и могут сравнивать текущий
состав через рейтинг на главной.

## Цели

- Добавить к аккаунту персонажа ПА, ПЗ, БУ, ХП, БД и текстовый «Источник».
- Разрешить чтение и изменение этих полей только администратору в карточке
  аккаунта.
- Показывать пять числовых показателей членам клана, офицерам и администраторам
  в карточках раздела «Состав».
- Добавить на главную рейтинг текущего состава с фильтром по классу и
  сортировкой по каждому из пяти показателей.
- Для уже существующих аккаунтов оставить новые поля пустыми; значения вводятся
  вручную.

## Не входит

- История изменения показателей.
- Показатели в группах событий.
- Импорт данных, общий балл или формула силы.
- Изменение рейтинга посещаемости и существующих правил доступа к другим
  разделам.

## Границы доступа

- Карточка аккаунта, пять полей и «Источник» доступны только администратору.
- Пять показателей попадают в состав и рейтинг только для внутренних ролей:
  `member`, `officer`, `admin`. Гостям, кандидатам и чтецам состав и рейтинг
  недоступны.
- «Источник» не возвращается в списке состава и в ответе для главной.
- Проверки выполняются сервером в единственной Edge Function `api`.

## Подходы

1. **Поля карточки профиля (выбран).** Пять показателей и источник хранятся
   рядом с текущим игровым ником и классом. У аккаунта один текущий игровой
   персонаж, поэтому отдельный объект или история не нужны. Изменение схемы
   выполняется новой совместимой миграцией.
2. **Отдельная таблица характеристик.** Изолировала бы поля, но добавила бы
   связь один-к-одному и дополнительные правила чтения/удаления без
   запрошенных нескольких персонажей или истории.

## Взаимодействие

### Администрирование

- В карточке аккаунта администратор видит раскрываемый блок «Характеристика
  персонажа» с полем «Источник» и отдельными полями ПА, ПЗ, БУ, ХП, БД.
- У каждого поля отдельное значение; после изменения оно сохраняется при
  потере фокуса, как в переданном HTML.
- Числовые поля допускают целое или десятичное число, десятичную запятую или
  точку и необязательный суффикс «к» для умножения на 1000. Пустое значение
  разрешено. Ошибочное значение не сохраняется; администратор видит сообщение
  у соответствующего поля.
- «Источник» — свободная строка до 160 символов, пустое значение разрешено.
- При ошибке сети сохранённое сервером значение остаётся источником истины;
  администратор получает сообщение и может повторить изменение.
- Административное изменение записывается в журнал с исполнителем,
  аккаунтом-целью и названием изменённого поля. Уведомление участнику не
  отправляется.

### Состав

- В карточке участника пять показателей всегда расположены под ником; отдельное
  раскрытие не используется.
- Пустой показатель отображается тире. «Источник» в карточке состава не
  показывается.
- На узком экране значения переносятся внутри карточки, горизонтальной
  прокрутки нет.

### Главная

- Отдельный блок «Рейтинг силы» показывает всех текущих участников состава,
  их класс и пять показателей.
- Фильтр по классу начинается со значения «Все классы».
- Начальный порядок — ПА по убыванию. Нажатие заголовка другого показателя
  сортирует по нему по убыванию; повторное нажатие меняет направление.
- Заполненные значения идут перед пустыми; одинаковые значения упорядочены
  по игровому нику.
- Пустой состав показывает существующее пустое состояние. Пустые отдельные
  показатели показываются тире.
- На телефоне строки представляются карточками без горизонтальной прокрутки.
- Рейтинг посещаемости за месяц остаётся без изменений.

## Данные и совместимость

- Текущие roster/account операции расширяются необязательными полями; порядок
  выкладки остаётся совместимым: сначала миграция и функция, затем клиент.
- Рейтинг использует тот же полный текущий список участников, что и раздел
  «Состав». Решение Q-48 ограничивает состав 200 участниками; защитный лимит
  API и сигнал об обрезке сохраняются.
- Новые значения не меняют дату вступления, роли, профильные личные сведения,
  посещаемость или исторические записи.
- Изменение значения в одном поле — отдельное сохранение и запись в аудит.

## Оставлено исполнителю

- Выбрать подходящую точность и верхнюю границу числового значения, безопасные
  для числовой сортировки и передаваемого формата; отвергать переполнение и
  ненумеруемые формы.
- Расширить контракт, репозиторий и сервисы так, чтобы `Источник` никогда не
  возвращался для чтения участникам.
- Добавить компонентные, серверные, pgTAP и затронутые e2e проверки, сиды и
  истории компонентов согласно правилам репозитория.
- На малой ширине использовать общие правила адаптивности и токены темы.
