# Вкладка подписок рассылки — план реализации

> **Для исполнителя:** выполнять задачи последовательно в этом сеансе, сверяясь с требованиями модуля перед изменениями. Шаги отмечаются флажками.

**Цель:** добавить в раздел «Рассылка» защищённую вкладку со статусами привязки мессенджеров всего внутреннего состава.

**Архитектура:** новое чтение `broadcasts/subscriptions` проверяет роль на сервере и возвращает курсорную страницу с ником, ролью и состояниями Telegram, ВКонтакте и MAX; поиск выполняется на сервере. Клиент хранит вкладку и поиск в адресе, загружает страницы через TanStack Query, отображает их через общий виртуальный список и показывает карточки на узком экране.

**Стек:** существующие TypeScript strict, одна Supabase Edge Function `api`, Zod, Kysely, React, TanStack Router/Query, Tailwind CSS, `MessengerIcon`, `VirtualList`.

**Требования:** `docs/requirements/14-broadcast.md` (BRC-15), `docs/requirements/01-roles.md`, решение Q-112 в `docs/requirements/17-open-questions.md`, `docs/architecture/lists.md`.

## Общие ограничения

- Только Node.js 24 и точные существующие зависимости; новые библиотеки не добавлять.
- Только одна Edge Function, Supabase Free и статический сайт GitHub Pages.
- Секреты не помещать в код, документы, тестовые данные, логи или ответы.
- Проверка права — на сервере; роли списка — `member`, `officer`, `admin`.
- Возвращать только ник, роль и состояния привязок; не возвращать email или иные поля профиля.
- Большие списки используют курсор, поиск на сервере, `useInfiniteQuery` и `VirtualList`.
- Узкий экран показывает карточки без горизонтальной прокрутки.

## Основные случаи для проверки

1. Офицер/администратор видит список, а член/кандидат/чтец получает отказ.
2. Страница после 50-й записи не дублирует и не пропускает участников; курсор продолжает сортировку по `(ник, id)`.
3. Поиск совпадает по нику без учёта регистра, начинается с первой страницы при изменении.
4. Три состояния канала различимы: привязан, остановлен, не привязан; строка выделяется, только если не привязан ни один канал.
5. Пустой результат, ошибка первой загрузки и ошибка следующей страницы имеют отдельные понятные состояния.
