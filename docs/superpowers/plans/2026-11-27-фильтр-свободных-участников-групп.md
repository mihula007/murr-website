# Фильтр свободного состава и сведения о группах — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать полный свободный список групп события с фильтром значками классов, общим счётчиком состава и доступной подсказкой характеристик участника группы.

**Architecture:** Добавить отдельную постраничную операцию `groups/pool-page` с фильтрами ответа и классов и серверными числами вкладок. Сведения участников каждой группы будут приходить с группой, независимо от загруженных страниц свободного списка. Клиент сохранит выбранные классы в адресе, использует существующую виртуализацию и обновит счётчик после изменения состава.

**Tech Stack:** TypeScript strict, React 19, TanStack Router, TanStack Query, TanStack Virtual, zod, Kysely и одна Supabase Edge Function `api`; новые зависимости и таблицы не добавлять.

**Spec:** [docs/superpowers/specs/2026-11-27-event-group-pool-filters-design.md](../specs/2026-11-27-event-group-pool-filters-design.md)

## Global Constraints

- Использовать существующий стек, одну Edge Function `api` и только Supabase Free.
- Для списка больше 50 использовать курсор, фильтры на сервере, `useInfiniteQuery` и виртуализацию TanStack Virtual.
- Сохранить сортировку по ПА/ПЗ/БУ/ХП/БД на всём списке; null остаются в конце в обоих направлениях, совпадения упорядочены по нику и ID.
- Изменения API делать совместимо; новые необязательные поля допустимы.
- Поиск по нику в свободном пуле отсутствует; несколько классов фильтруются значками, пустой выбор означает все классы.
- Член клана и офицер без `events.view_full_roster` видят только свою группу; полный состав видят мастер, администратор и офицер с этим правом.
- Закрытые снимки события не дополняются характеристиками; на закрытых событиях подсказка не показывается.
- Не менять данные, роли, уведомления и записи журнала; не запускать e2e локально.

## Review Focus

1. Список с 251+ участниками: курсор не пропускает и не повторяет строки; проверяет Task 2.
2. Назначенные участники не появляются в свободном пуле, а перенос обратно возвращает их в соответствующую вкладку; проверяют Tasks 2–3.
3. Пустой выбор значков означает все классы, множественный выбор работает по всему списку, сортировка по характеристикам учитывает все страницы, а числа вкладок не меняются от фильтра и сортировки; проверяют Tasks 2–3.
4. Член клана и офицер без `events.view_full_roster` не получают полный пул и не видят общий счётчик; проверяют Tasks 2–3.
5. Пустые характеристики показываются тире, а закрытые события не получают текущие значения профиля; проверяют Tasks 1 и 3.
