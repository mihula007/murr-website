Пропуски Playwright: сценарии аккаунта не повторяются на проекте `pages-subpath` (подпуть проверяют каркасные тесты), меню по ролям на `mobile` проверяет навигационный тест этапа 2.

**Окружение.** Node 24 через nvm (системный Node 22). Playwright 1.65 не поставляет Chromium для macOS 13 — тесты шли теми же проектами с `channel: 'chrome'` через временный конфиг вне репозитория; в CI — обычный Chromium. Машина владельца медленная: локально Playwright работает в один поток (`workers: 1`), в CI — в два. Studio Supabase на этой машине не проходит health check за 2 секунды, поэтому стек запускался `npx supabase start -x studio`; на остальные сервисы это не влияет.

## Ручная проверка

Dev-сервер с локальным Supabase (`npm run supabase:env`), Playwright MCP с Chrome, ширины 375 / 768 / 1240 px.

1. **Регистрация.** Пустая отправка показывает ошибки у всех полей, включая аватар; фокус переходит на первое поле с ошибкой. Предпросмотр аватара, классы из БД, подсказка о занятом нике, до 10 ссылок. Письмо приходит в Mailpit с шестизначным кодом.
2. **Код, завершение, вход, сброс пароля.** Экраны работают на 375 px без горизонтальной прокрутки; таймер повторной отправки.
3. **Кабинет.** Приветствие, статус заявки, аватар 76 px, раскрывающиеся «Личная информация» и «Смена пароля», редактирование с предзаполнением, email только для чтения, «Выйти».
4. **Шапка.** Гость — «Вход», вошедший — «Аккаунт»; меню по роли с сервера.

Прототип открывался через локальный статический сервер, файлы не менялись; кабинет показан подстановкой демо-пользователя в памяти страницы.

| Экран       | Ширины    | Итог                                                                                          |
| ----------- | --------- | --------------------------------------------------------------------------------------------- |
| Регистрация | 1240, 375 | Совпадает: карточка 620 px, сетка в две колонки, круг аватара, золотая кнопка на всю ширину   |
| Вход        | 1240      | Совпадает: подписи, поля, «Забыли пароль?»                                                    |
| Кабинет     | 1240, 375 | Совпадает: «Привет, …», бейдж статуса, фото 76 px, раскрывающиеся блоки, уведомление, «Выйти» |

Осознанные изменения:

- Анкета разбита заголовками «Аккаунт», «Персонаж», «О себе»; ошибки показываются у полей, а не всплывающим сообщением.
- Скриншоты снаряжения — до 10 ссылок вместо файлов (Q-11, уточнение владельца).
- Заголовок кабинета «Личный кабинет» (в прототипе оставался «Вход в Murr»).
- Поля смены пароля — в одну колонку: в три колонки подписи переносились и поля съезжали.
- Убрано уведомление о демо-режиме; добавлены экраны кода, завершения регистрации и сброса пароля, которых в прототипе нет.

## Отличия от плана

- **Функция без supabase-js.** Под параллельной нагрузкой изоляты функции упирались в лимит CPU и перезапускались; холодный старт был 3,2 с. Проверка JWT (`/auth/v1/user` вместо `getClaims`) и Storage переведены на `fetch`: холодный старт 0,9 с. Правило записано в `AGENTS.md`.
- **Версии пакетов сервера** выбраны не самые свежие, а зрелые: `kysely` 0.29.7, `kysely-postgres-js` 5.0.1, `postgres` 3.4.9 (самым новым было несколько дней).
- **Занятый ник** — ошибка поля `nickname_taken` внутри `validation_failed`, а не отдельный код API.
- **Скрипты.** Вместо `e2e-env.mjs` — общий `scripts/supabase-env.mjs` для `dev` и e2e; хелперы e2e — один файл `e2e/supabase.ts`.
- **Q-35** (бессрочная сессия) принято владельцем во время этапа; добавлены настройки и тест конфигурации.
- **CI.** Браузерные тесты перенесены из задания `check` в новое задание `backend` с локальным Supabase.
- **Storybook.** Истории для новых экранов не добавлялись: `build-storybook` сломан ещё до этапа 2, формы покрыты Vitest и Playwright.
- **Исправлено по ходу e2e:** после «Выйти» кабинет сам перенаправлял гостя на `/login` раньше перехода на главную.
- **«Прямой запрос к чужому профилю».** Отдельных операций над чужими объектами на этапе 3 нет; проверено, что таблицы закрыты для Data API, Storage не отдаёт чужой аватар напрямую, а `account/me` возвращает только свой профиль.

## Не проверено

- Запуск задания `backend` в GitHub Actions: изменения не отправлялись в удалённый репозиторий.
- Реальная отправка писем через Resend (SMTP выключен локально, домен не выбран — этап 12).
- Лимиты CPU и время холодного старта Edge Functions в облачном Supabase Free.
- Кодирование аватара в WebP в Safari (есть запасной JPEG), реальные мобильные устройства, скринридеры, Firefox.
- Очистка неподтверждённых пользователей Auth без профиля — административная задача этапа 11.
