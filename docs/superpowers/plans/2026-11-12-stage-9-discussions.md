# Этап 9. Обсуждения — план реализации

> **Для исполнителя:** используйте superpowers:executing-plans, задачи выполняются по порядку; шаги отмечаются чекбоксами. Это подробный план этапа 9 из [мастер-плана](2026-11-08-master-plan.md). **Статус: выполнен 12.11.2026** (согласован владельцем 12.11.2026); проверка — [журнал](2026-11-12-stage-9-verification.md). Решения до старта — Q-58–Q-63.

**Цель:** у каждого события, голосования, публикации и торгового объявления есть своя ветка обсуждения. Внутренние участники пишут сообщения до 2000 символов, отвечают с цитатой, вставляют эмодзи, упоминают `@ник`, правят своё сообщение 5 минут, ставят реакции и видят, кто прочитал. Завершённый родитель оставляет историю только для чтения.

**Архитектура.** Как на этапах 3–8: обработчик функции `api` → сервис `discussions` → репозиторий (Kysely). Права на ветку сервис не хранит, а выводит из родителя через небольшие функции доступа модулей `events`, `votes`, `publications`, `market` (каждый модуль отвечает за свои правила видимости). Уведомления об упоминаниях и ответах — существующий `notify(tx, …)` в транзакции отправки. Клиент — общий модуль `src/features/discussions/` с компонентом `DiscussionThread`, встроенным в страницу события и в окно обсуждения остальных родителей.

**Требования:** DSC-01–15, VOT-13, PUB-08, MKT-10, Q-20 (набор функций не расширяется), часть E2E-04 «читает и обсуждает». Не входят: колокольчик и список уведомлений (этап 10 — здесь уведомления только записываются), удаление пользователя (DSC-16, DSC-17 — процедура этапа 11; здесь только схема `ON DELETE`), модерация и удаление сообщений (их нет по Q-20).

## Решения владельца (12.11.2026)

- **Q-58.** Окно обновляется опросом раз в 30 с, только пока оно открыто и вкладка видима; после своего действия ветка перечитывается сразу. Realtime не используется.
- **Q-59.** Список прочитавших видят автор сообщения, офицеры и администратор; автор всегда видит «прочитано» у своих сообщений.
- **Q-60.** Реакции: ❤️ 👍 👎 😂 🔥 😢 😭 😐 👌 🤡.
- **Q-61.** Меню сообщения: правый клик, кнопка «⋯» (на сенсорном экране видна всегда, на десктопе — при наведении и фокусе) и долгое нажатие.
- **Q-62.** Ветка — большой список (курсор, виртуализация); «кто прочитал» и «кто поставил реакцию» — по исключению Q-48, целиком.
- **Q-63.** Действия в обсуждениях в аудит не пишутся.

## Решения исполнителя (можно оспорить при согласовании)

- **Ветка — отдельная строка.** Таблица `discussion_threads` с четырьмя nullable FK (`event_id`, `vote_id`, `publication_id`, `market_listing_id`), `CHECK` ровно одного родителя, `UNIQUE` на каждый FK и `ON DELETE CASCADE` от родителя (DSC-14: удаление материала очищает ветку). Сообщения, реакции и прочтения ссылаются на `thread_id`. Мастер-план предлагал четыре FK прямо в сообщениях; одна строка ветки убирает повтор этой проверки в трёх таблицах. Ветка создаётся при первом сообщении (`INSERT … ON CONFLICT DO NOTHING`), пустую ветку сервис отдаёт без записи.
- **Прочтение — отметка «прочитано до» на ветку,** а не строка на каждое сообщение: `discussion_reads (thread_id, user_id, read_up_to)`. Сообщение прочитано пользователем, если `read_up_to ≥ created_at` сообщения. Клиент отправляет отметку, когда низ ветки виден в открытом окне (DSC-12 «видимые сообщения»). 200 участников × тысячи сообщений построчно — это сотни тысяч строк в Free-базе; отметка на ветку — не больше 200 строк. Она же пригодится счётчикам непрочитанного этапа 10. Отметки удаляются вместе с пользователем (`ON DELETE CASCADE`, DSC-17).
- **Состояние «прочитано» у своих сообщений** — по полю `othersReadUpTo` ответа (самая поздняя отметка других участников): клиент сравнивает с временем сообщения, отдельного запроса нет. Список прочитавших (`discussions/readers`) — по запросу из меню, только автору, офицеру и администратору (Q-59).
- **Доступ следует родителю.** Читают ветку те, кто видит родителя: событие и голосование — член, офицер, администратор; публикация и объявление — те, кто видит материал. Пишут (отправка, ответ, правка, реакция), только если: событие и голосование не завершены (`closed_at IS NULL`, DSC-13); материал опубликован и обсуждение включено (DSC-14). Выключенное обсуждение и снятие с публикации оставляют историю читаемой тем, кто видит материал, но закрывают запись; кнопка обсуждения у материала с выключенным обсуждением и без сообщений не показывается. Кандидат, чтец и гость получают `forbidden`, чужой черновик — `not_found` (как в этапе 8). Запись в закрытую ветку — `state_conflict`. Родитель блокируется `FOR SHARE` при записи, чтобы сообщение не проскочило после завершения (как голос в этапе 5).
- **Правка (DSC-08, DSC-09)** — только автор, пока `now() − created_at < 5 мин` по `deps.now()`, и ветка открыта для записи; иначе `state_conflict` (форма, открытая заранее, тоже получает отказ). Пустая правка — `validation_failed`. Сохраняются `edited_at`, интерфейс помечает «изменено». Права офицера и администратора на чужие сообщения нет. Правка не создаёт новых уведомлений (Q-20: без новых функций; повтор отправки дедуплицируется `source`).
- **Ответ (DSC-05)** — `reply_to_id` на сообщение той же ветки (проверка в сервисе). Цитата показывается по текущему тексту и автору исходного сообщения (первые 200 символов), не копируется.
- **Упоминания (DSC-07)** — `@ник` без учёта регистра по `game_nickname` (он уникален, Q-12) среди тех, кто может читать ветку. Новые виды уведомлений `discussion_mention` и `discussion_reply` (миграция расширяет `CHECK`), источник — сообщение. Если адресат ответа ещё и упомянут — одно уведомление об ответе. Себе уведомление не создаётся (`notify` уже это проверяет). Ссылка уведомления ведёт на родителя.
- **Реакции (DSC-11, Q-60)** — `discussion_reactions (id, message_id, user_id NULL, emoji, created_at)`, `UNIQUE (message_id, user_id, emoji)`; `user_id ON DELETE SET NULL` — реакции удалённого остаются обезличенными (DSC-17, Q-33). Повторный выбор снимает свою реакцию (одна операция `toggle`). Набор эмодзи — константа в `@contracts/discussions`, проверяется zod.
- **Обновление (Q-58)** — у каждого сообщения `changed_at`: время создания, правки или изменения реакций. Опрос `discussions/changes { thread, since }` возвращает сообщения с `changed_at > since` (не больше 100; если больше — `reset: true`, клиент перечитывает первую страницу) и `othersReadUpTo`. `refetchInterval: 30 000` только при открытом окне и `document.visibilityState === 'visible'`. Оценка квоты: 30 человек × 30 мин/день с открытым окном ≈ 54 тыс. вызовов в месяц из 500 тыс. Free — перепроверить актуальный лимит перед реализацией.
- **Счётчик сообщений (DSC-01)** — поле `messageCount` в ответах `events/list|get`, `votes/list|get`, `publications/list|get`, `market/list|get` (новое необязательное поле — совместимое изменение). Считается запросом `count` по индексу `(thread_id)` для карточек страницы, без отдельной колонки-счётчика (как итоги голосований).
- **Текст безопасен (DSC-04)** — хранится как обычный текст, показывается текстом React (`whitespace-pre-wrap`), без разметки и `innerHTML`; ссылки не превращаются в теги (Q-20 — прототип этого не делал). Ограничение 1–2000 символов после `trim` — zod в `LIMITS` и `CHECK` в схеме.
- **Эмодзи (DSC-06)** — небольшая сетка популярных эмодзи в `Popover`-меню без библиотеки; вставка в позицию курсора `textarea`. Набор шире реакций, константа в клиенте.
- **Где показывается (DSC-01, DSC-15).** Событие — блок «Обсуждение» рядом с группами (на ≥ 1024 px — колонка справа, на узком экране — вкладка «Обсуждение» на странице события). Голосование, публикация, объявление — кнопка «Обсуждение (N)» открывает `Dialog` (на узком экране — во всю высоту); закрывается кнопкой, Escape и кликом вне, фокус возвращается на кнопку (Radix делает это сам, проверяется тестом). Отправка — кнопка или Ctrl/Cmd+Enter, Enter — перенос строки (DSC-03).
- **Виртуализация ветки.** `VirtualList` работает от прокрутки окна, а ветка прокручивается внутри своего блока и растёт вверх. В `src/components/virtual-list.tsx` добавляется вариант `useElementList` на `useVirtualizer` с прокруткой контейнера, привязкой к низу и сохранением позиции при подгрузке старых сообщений. Это тот же файл и те же переменные `--virtual-*` — правило стилей не меняется.
- **Роль автора (DSC-02)** — текущая роль профиля: значок «Офицер» / «Админ». Удалённый автор — «Пользователь удалён» (`author_id ON DELETE SET NULL`, DSC-16), ответы на его сообщения сохраняются.
- **Лимиты (`LIMITS`)** — сообщение ≤ 2000 символов, страница 50, `changes` ≤ 100. Защиты от частой отправки нет (Q-20); при злоупотреблении — отдельное решение.

## Операции функции `api`

Ветка в запросе — `{ parent: 'event' | 'vote' | 'publication' | 'market', parentId }`.

| Маршрут                 | Кто                             | Что делает                                                                                                              | Аудит |
| ----------------------- | ------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----- |
| `discussions/list`      | видит родителя                  | `{ thread, cursor?, limit? } → { items, nextCursor, canWrite, othersReadUpTo, now }`; цитаты и реакции (счётчики, свои) | нет   |
| `discussions/changes`   | видит родителя                  | `{ thread, since } → { items, reset, othersReadUpTo, canWrite, now }`                                                   | нет   |
| `discussions/send`      | видит родителя, ветка открыта   | Сообщение, `replyToId?`; уведомления об упоминании и ответе в той же транзакции                                         | нет   |
| `discussions/edit`      | автор, 5 минут, ветка открыта   | Новый текст, `edited_at`, `changed_at`                                                                                  | нет   |
| `discussions/react`     | видит родителя, ветка открыта   | Ставит или снимает свою реакцию                                                                                         | нет   |
| `discussions/mark-read` | видит родителя                  | Поднимает `read_up_to` до переданного времени (не выше `now`, не опускает)                                              | нет   |
| `discussions/readers`   | автор сообщения, officer, admin | Прочитавшие сообщение (без автора)                                                                                      | нет   |
| `discussions/reactions` | видит родителя                  | Кто поставил какие реакции                                                                                              | нет   |

Новых кодов ошибок нет: `validation_failed`, `forbidden`, `not_found`, `state_conflict`.

## Задачи

### Задача 1. Схема

- [x] Миграция: четыре таблицы, `CHECK (num_nonnulls(event_id, vote_id, publication_id, market_listing_id) = 1)`, `UNIQUE` на каждый FK, `ON DELETE CASCADE` от родителей; `discussion_messages.author_id ON DELETE SET NULL`, `reply_to_id` на сообщение (`ON DELETE SET NULL`), `CHECK char_length(body) BETWEEN 1 AND 2000`; `discussion_reactions.user_id ON DELETE SET NULL`, `CHECK emoji IN (…)`; `discussion_reads.user_id ON DELETE CASCADE`, PK `(thread_id, user_id)`.
- [x] Индексы: `(thread_id, created_at DESC, id DESC)`, `(thread_id, changed_at)`, реакции `(message_id)`, автор `(author_id)`.
- [x] Расширить `CHECK kind` у `user_notifications`. RLS включён, `REVOKE` для Data API-ролей.
- [x] pgTAP: Data API-роли без доступа; два родителя и ни одного — отклоняется; удаление события/голосования/публикации/объявления удаляет ветку; удаление профиля обезличивает сообщение и реакцию и удаляет отметку прочтения.
