# Фильтры и сортировка аккаунтов — план реализации

> **Для исполнителя:** выполнять пункты последовательно с проверкой после каждого; тесты писать до кода.

**Цель:** дать администратору серверные фильтры аккаунтов по классу и роли и оставить сортировку по нику и дате регистрации.

**Подход:** расширить существующий список аккаунтов: фильтры, подсчёт и сортировка остаются в одном серверном запросе с курсорной подгрузкой. Значения хранятся в адресе; справочник классов берётся через существующий `catalog/classes` с его кешем. На телефоне выбор фильтров открывается кнопкой.

**Стек:** TypeScript, React, TanStack Router, TanStack Query, zod, Supabase Edge Function, Vitest, Playwright.

**Требования:** [15-admin.md](../../requirements/15-admin.md) (ADM-02, ADM-17), решение Q-113 в [17-open-questions.md](../../requirements/17-open-questions.md).

## Общие ограничения

- Клиент — статические файлы React + Vite на GitHub Pages.
- Backend — только Supabase Free и одна Edge Function `api`; каждый запрос — отдельный вызов функции.
- Чтение — через TanStack Query; параметры перехода — через TanStack Router.
- Валидация — zod из `supabase/functions/_shared/contracts/`.
- Большой список (> 50) использует серверные фильтры и поиск, курсорную подгрузку и виртуализацию.
- Права на полный список аккаунтов остаются только у администратора.

## Файлы

- `supabase/functions/_shared/contracts/accounts.ts` — допустимые поля сортировки и фильтры запроса.
- `supabase/functions/_shared/accounts/repository.ts` и `service.ts` — единый отбор для страницы и `total`, курсор по нику/дате регистрации.
- `src/features/admin/query-keys.ts`, `api.ts`, `admin-page.tsx`, `accounts-panel.tsx` — параметры списка, URL, загрузка и поля интерфейса.
- `tests/server/admin.test.ts` — серверный поиск, фильтры, сортировка, число и курсор.
- `tests/admin-accounts-filters.test.tsx` — URL и поведение фильтров/сортировки, включая телефонную кнопку.
- `e2e/admin.spec.ts` — полный сценарий аккаунтов на широком и узком окне.
- `docs/requirements/15-admin.md` — статус ADM-02 и ADM-17 после реализации.

## Проверка на крайних случаях

- Класс и роль применяются вместе и вместе с поиском; `total` и следующая страница используют тот же отбор.
- Пустой результат после поиска или фильтра показывает «Ничего не найдено».
- Равные значения сортировки не пропускают и не дублируют аккаунты при переходе курсором.
- Старый или неизвестный вариант сортировки в ссылке безопасно заменяется сортировкой по нику.
- Ошибка загрузки справочника классов предлагает повторить загрузку и не меняет данные аккаунтов.
