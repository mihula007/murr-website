# Этап 2. Общий интерфейс и навигация — план реализации

> **Для исполнителя:** используйте superpowers:executing-plans, задачи выполняются по порядку; шаги отмечаются чекбоксами. Это подробный план этапа 2 из [мастер-плана](2026-11-08-master-plan.md). **Статус: проект для согласования, к реализации не приступать без согласия владельца.**

**Цель:** оболочка приложения «Murr клан» — шапка с меню по ролям, мобильная навигация, заглушки всех разделов, общие состояния, защита от потери несохранённых данных и заставка. Без бизнес-логики и без обращения к Supabase.

**Архитектура.** Права видимости описаны декларативно (`src/app/access.ts`, `src/app/navigation.ts`) и проверяются чистыми функциями. Текущая роль приходит из `AccessProvider`: в production это всегда `guest`, в dev-режиме — выбранная в переключателе. На этапе 3 провайдер подключается к реальной сессии, остальной код не меняется. Доступ к маршруту проверяет компонент `RouteGate`; серверной защиты на этом этапе нет, потому что данных нет.

**Стек:** React 19, TanStack Router (hash), Tailwind 4, shadcn/ui на Radix, Vitest + Testing Library, Playwright, Storybook.

## Решения владельца (08.11.2026)

- Гость в production видит только публичное меню; внутренние маршруты зарегистрированы и ведут на «Нет доступа» с приглашением войти.
- Заставка входит в этап 2 и обязательна для финального вида.
- Название везде — «Murr клан».

## Ограничения

- Прототип не изменяется; его ресурсы только копируются (`prototype/assets/murrclan-intro.png`).
- Версии новых зависимостей — точные, определяются командой `npm view <пакет> version` при установке; `package-lock.json` коммитится.
- В Git добавляются только перечисленные файлы. В рабочем дереве уже есть чужие правки (`npm ci` → `npm clean-install` в README, AGENTS.md, workflows, package.json) — не включать их в коммиты этапа без согласования; правку `package.json` для зависимостей вносит `npm install`, поэтому перед первым коммитом зависимостей решить с владельцем, коммитить ли те правки вместе.
- Мобильная проверка (375 px) и desktop (1240 px) обязательна для каждой задачи с интерфейсом.

## Задача 2. Модель доступа и конфигурация навигации (TDD)

**Файлы:** `src/app/access.ts`, `src/app/navigation.ts`, `tests/navigation.test.ts`.

Модель:

```ts
export type AccessRole =
  'guest' | 'applicant' | 'reader' | 'member' | 'officer' | 'admin'
export const INTERNAL_ROLES: readonly AccessRole[] = [
  'member',
  'officer',
  'admin',
]
export const MANAGER_ROLES: readonly AccessRole[] = ['officer', 'admin']
```

Разделы (источник — таблица ACL и карта страниц): `events`, `votes`, `roster`, `publications`, `market`, `rating` — для `INTERNAL_ROLES`; `applications`, `activity`, `broadcast` — для `MANAGER_ROLES`; `admin` — только `admin`. Категории: «Клан» (events, votes, roster), «Сообщество» (publications, market, rating), «Управление» (applications, activity, broadcast, admin). У каждого раздела: `id`, `path`, `label`, `category`, `roles`.

## Риски и допущения

- **`useBlocker` с hash-историей:** поведение подтверждается тестом в задаче 7; при несовместимости — запасной вариант через `router.history.block` с тем же интерфейсом хука.
- **Вес заставки:** большое изображение замедлит первую загрузку на Pages — задача 8 включает оптимизацию и ленивую загрузку (`loading="eager"`, но с `decoding="async"` и фоном, видимым до загрузки).
- **Заставка перекрывает контент для e2e и скринридеров:** решается `inert` у оболочки и helper'ом метки активности в тестах.
- **Dev-инструмент в production:** закрывается проверкой в задаче 9; при срабатывании — остановить публикацию.
- **Содержимое заглушек** («Раздел в разработке») видно только вошедшим ролям; гость видит «Нет доступа».
