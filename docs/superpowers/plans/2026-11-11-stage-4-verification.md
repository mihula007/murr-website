Пропуски Playwright: сценарии аккаунта, заявок и членства не повторяются на `pages-subpath` (подпуть проверяют каркасные тесты); прямые вызовы запрещённых операций проверяются один раз, в проекте `chromium`.

Новые сценарии: E2E-02 (`e2e/applications.spec.ts`), отказ и новая заявка со второй вкладкой, E2E-06 и прямые запрещённые вызовы токенами кандидата, члена и офицера (`e2e/membership.spec.ts`). Кандидат создаётся через Auth API и Mailpit без интерфейса; офицер и администратор — прямой записью в локальную БД.

**Окружение и наблюдения.** Docker Desktop перед проверкой был выключен и запущен заново; стек — `npx supabase start -x studio`, функции — `npx supabase functions serve`. Тест `tests/staged-secrets.test.ts` однажды не уложился в 5 с при нагруженной машине (Docker + стек) и прошёл при повторе; отдельно он занимает около 5,2 с — запас у таймаута маленький.

## Ручная проверка

Dev-сервер с локальным Supabase (`npm run supabase:env`), Playwright по сценарию из временной папки; ширины 375 / 768 / 1240 px; роли: офицер, администратор, член, кандидат с новой заявкой, кандидат после отказа, чтец. Всего 60 экранов: ни на одном нет горизонтальной прокрутки и ошибок страницы; «Нет доступа» — ровно там, где ожидается (член — «Заявки», кандидат и чтец — «Состав»).

1. **Заявки (офицер, администратор).** Очередь «Новые» со счётчиком и «Решённые»; карточка: аватар 72 px, ник, класс, имя, рассказ, ссылки в новой вкладке. Блок «Личные данные» (email, город, дата рождения) — только у администратора. Диалог решения с примечанием.
2. **Состав.** Панель численности и классов, фильтр, карточки 1/2/3 колонки, иконки классов; «Присвоить статус «Чтец»» только у администратора на картах членов; блок «Чтецы» у офицера и администратора.
3. **Администрирование.** Таблица аккаунтов, недоступный выбор роли с пояснением. **Исправлено в ходе проверки:** на 768 px таблица была ещё табличной и email разрывался посередине — карточки теперь до 900 px, а не до 760.
4. **Главная и кабинет.** Численность для всех ролей; путь кандидата по этапам (2 колонки на 768 px, 5 на 1240 px); после отказа — «Подать новую заявку» и страница новой заявки; чтец — права гостя, кабинет доступен.

## Сравнение с прототипом

Прототип открывался локальным статическим сервером, файлы не менялись; администратор и кандидат подставлены в память страницы.

| Экран  | Ширины    | Итог                                                                                                                                     |
| ------ | --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Заявки | 1240, 375 | Совпадает визуальный язык: тёмные карточки, золотые акценты, кнопки решения под анкетой                                                  |
| Состав | 1240, 375 | Совпадает: панель статистики (крупное число, разделитель, чипы классов с иконкой и счётчиком), фильтр класса, сетка карточек в 3 колонки |

Осознанные отличия:

- В очереди нет email кандидата: офицер не получает его по APP-03 / ACL-10. Анкета открывается отдельной страницей, а не раскрытием `<details>` в списке; «Передать на голосование» — этап 5.
- Кнопка «Принять» вместо «Принять сразу»: в этапе 4 нет другого способа приёма, подтверждение диалогом объясняет, что голосования не будет.
- На карточке состава нет личного имени (в прототипе — «Имя не указано» / имя), потому что ROS-02 запрещает его показывать. Вместо крупной иконки класса 52 px — аватар 40 px (план) и иконка класса рядом с названием.
- Заголовок «Состав» и фильтр стоят над панелью статистики, а не слева от неё; на 1240 px фильтр и панель — в одной строке.
- В панели классы без участников не показываются (как в прототипе); фильтр предлагает весь справочник.

## Не проверено

- Запуск заданий CI в GitHub Actions: изменения не отправлялись в удалённый репозиторий.
- Время холодного старта и лимиты CPU функции `api` с новыми операциями в облачном Supabase Free; новых зависимостей у функции нет.
- Реальные мобильные устройства, Safari и Firefox, скринридеры; на мобильных проверялась эмуляция Pixel 7 и ширина 375 px.
- Поведение открытой вкладки при смене роли без ответа `forbidden` (обновление `me` через 60 с или при перезагрузке) проверено только тестами, не вручную.
- В локальной БД остались тестовые пользователи e2e и ручной проверки; `npm run test:server` очищает прикладные данные, учётные записи Auth остаются.
