# Динамика развития участника — план реализации

> **Для исполнителя:** обязательно следовать навыку `executing-plans` и выполнять план по задачам. Шаги отмечаются флажками `- [ ]`.

**Цель:** Добавить в карточку состава окно с историей характеристик персонажа и недельной посещаемостью.

**Архитектура:** Добавить таблицу истории характеристик с исходным снимком при выкладке и атомарной записью изменений при ручном сохранении профиля. Серверные операции `roster/dynamics/*` проверяют текущую внутреннюю роль вызывающего и выбранного участника; история характеристик и недельные итоги выдаются курсорами, а UI рисует их средствами SVG в окне карточки состава.

**Технологии:** TypeScript strict, React, TanStack Query, zod, Supabase Postgres/Kysely, одна Edge Function `api`, Vitest, pgTAP и Playwright.

**Спецификация:** `docs/superpowers/specs/2026-11-23-character-dynamics-design.md`; требования DYN-01–10, ROS-16–17, ACT-20 и Q-118–Q-122.

## Общие ограничения

- Работа только в `main`; ветки и отдельные рабочие копии не создавать.
- Backend — одна Edge Function `api`, только Supabase Free; каждая выборка идёт через `callApi`.
- Новая история характеристик закрыта для браузерных ролей и читается только через проверенную серверную операцию.
- Текущие характеристики, аудит и запись истории изменения коммитятся одной транзакцией.
- При удалении профиля история удаляется каскадно; перевод в чтецы историю сохраняет.
- История характеристик и недель может превышать 50 точек: API cursor pagination, клиент доступен весь выбранный период.
- Новая зависимость и новые секреты не нужны; графики SVG в React с токенами темы.
- `scripts/seed-dev.ts` создаёт точки истории и закрытые события для ручной проверки.
- Локально e2e не запускать; их запускает CI при выкладке.

## Риски, не покрытые основными тестами

- Пустое имя или дата вступления: имя скрыть, дату показать тире.
- Профиль, роль или удаление меняются одновременно с чтением: сервер проверяет роль актуально; удаляемая цель недоступна.
- Несколько характеристик имеют разные шкалы: показывать отдельными панелями, каждую с собственной шкалой.
- Граница недели/года и выбранного периода: календарные недели и даты считать по Москве, для активности брать начало ивента.
- Много одинаковых по времени изменений: курсор дополнительно сортирует по уникальному ID и не пропускает точки.

## Файлы и ответственность

- `docs/requirements/23-character-dynamics.md`: центральный контракт функции.
- `supabase/migrations/*character_stat_history.sql`: закрытая таблица истории, индексы и исходные значения профилей на момент миграции.
- `supabase/functions/_shared/db/schema.ts`, `database.types.ts`: тип таблицы для Kysely и сервера.
- `supabase/functions/_shared/accounts/service.ts` и repository: атомарно писать каждое изменённое числовое поле при обеих операциях сохранения характеристик.
- `supabase/functions/_shared/roster/dynamics-service.ts` (или существующий `roster/service.ts`): zod-ввод и проверка внутренней роли цели/вызывающего.
- `supabase/functions/_shared/roster/dynamics-repository.ts`: заголовок, курсорная история чисел и агрегирование посещений по неделям МСК.
- `supabase/functions/_shared/contracts/roster-dynamics.ts`: поля, фильтры периода, курсоры и ответы.
- `supabase/functions/_shared/app.ts`: маршруты `roster/dynamics/profile`, `roster/dynamics/stats`, `roster/dynamics/attendance`.
- `src/features/roster/dynamics-api.ts`: три `useQuery`/`useInfiniteQuery`, фильтры входят в ключ кеша.
- `src/features/roster/member-dynamics-dialog.tsx` и `src/features/roster/dynamics-chart.tsx`: окно и доступные SVG-графики.
- `src/features/roster/roster-page.tsx`: открыть динамику с карточки.
- `scripts/seed-dev.ts`: воспроизводимые профили с исходной точкой, несколькими изменениями и посещениями за недели.
- `tests/server/roster-dynamics.test.ts`, `tests/character-stat-history.test.ts`, `tests/roster-dynamics.test.tsx`, `supabase/tests/database/stage21_character_dynamics.test.sql`, `e2e/roster-dynamics.spec.ts`: проверки доступа, истории, графиков и приёмки.
- `tests/server/user-deletion.test.ts`: проверить каскадное удаление истории.
