# Публичные голоса и карточки на главной — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить настраиваемую публичность обычных голосований, удобный список ответов и полные карточки актуальных голосований на главной.

**Architecture:** Признак публичности хранится в `app.votes` и возвращается контрактами голосования. Edge Function остаётся единственным источником решения, можно ли вернуть имена и отдельные ответы; главный экран использует существующий список голосований и общие карточки.

**Tech Stack:** TypeScript strict, React 19, TanStack Form/Query, zod, Supabase Postgres/Edge Function, Vitest, pgTAP и Playwright e2e.

**Spec:** `docs/requirements/07-votes.md` (VOT-18–19), `docs/requirements/16-home.md` (HOM-21), `docs/requirements/17-open-questions.md` (решение от 22.11.2026).

## Global Constraints

- Одна Edge Function `api`; только Supabase Free и статический сайт GitHub Pages.
- Миграции только вперёд; существующие голосования после добавления поля остаются непубличными.
- Большие списки ограничиваются `MEMBER_LIST_LIMIT`; секреты остаются вне клиентского кода.
- На телефоне карточки и список ответов не требуют горизонтальной прокрутки.

## Review Focus

- Обычное создание и создание голосования по заявке не смешивают публичность: поле недоступно заявочному типу и по умолчанию false.
- Смена роли или права офицера не позволяет кандидату/чтецу получить отдельные голоса.
- Непубличные голосования сохраняют прежние правила для member и officer.
- Фильтр не меняет результаты голосования и справляется с пустым ответом.
- Главная остаётся пригодной при нуле, одном и нескольких актуальных голосованиях и на узком экране.

## Файлы и ответственность

- `docs/requirements/*`: поведенческий контракт и решение сопровождающего.
- `supabase/migrations/*`: совместимое поле `is_public`, false для старых строк и ограничение на тип `general`.
- `supabase/functions/_shared/contracts/votes.ts`, `votes/service.ts`, репозитории и DB-типы: контракт, сохранение и серверное управление видимостью голосов.
- `src/features/votes/*`: переключатель при создании, фильтр и внутренняя прокрутка списка голосов.
- `src/features/home/member-home.tsx`: карточки актуальных голосований через общий компонент.
- `tests/server/votes.test.ts`, `tests/votes.test.tsx`, `tests/home.test.tsx`, `e2e/votes.spec.ts`, pgTAP: доказательства доступа, UI и миграции.
