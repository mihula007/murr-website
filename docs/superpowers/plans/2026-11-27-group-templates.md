# Расширение шаблонов групп — план реализации

> **Для исполнителя:** выполнять этот план последовательно в текущем сеансе; шаги используют чекбоксы для отслеживания.

**Цель:** расширить конструктор шаблонов групп, показывать характеристики и фильтрованный большой состав, а также дать возможность редактировать общий шаблон.

**Архитектура:** оставить прежние операции чтения списка и сохранения рабочими для уже открытых версий сайта. Добавить краткий каталог шаблонов и отдельное чтение выбранного шаблона с характеристиками; сохранение принимает необязательный ID и транзакционно обновляет текущий шаблон. Свободный состав загружается существующей курсорной операцией `roster/page`; конструктор использует `useInfiniteQuery`, серверный поиск/фильтр класса и виртуализированный список.

**Стек:** TypeScript strict, React 19, TanStack Query, TanStack Form, Zod, Supabase Edge Function `api`, Tailwind CSS 4, Vitest, Playwright.

**Требования:** [docs/requirements/06-groups.md](../../requirements/06-groups.md), GRP-20–22; решение от 27.11.2026 в `docs/requirements/17-open-questions.md`.

## Общие ограничения

- Node.js 24 LTS; версии пакетов точные; зависимости устанавливать только `npm clean-install`.
- Клиент — React + Vite на GitHub Pages; backend — Supabase Free и одна Edge Function `api`.
- Новые поля API — необязательные либо новая операция рядом со старой; существующий клиент остаётся совместимым.
- Большой список (> 50): курсорная пагинация, фильтр/поиск на сервере, `useInfiniteQuery`, виртуализация.
- Tailwind использует только токены темы; новых библиотек и таблиц БД не добавлять.
- Пользовательские тексты и документация — на русском; секреты не попадают в код, тесты, логи и документацию.

## Основные риски для проверки

1. Изменение чужого или отсутствующего шаблона: запрещённый офицер получает `forbidden`, неизвестный ID — `not_found`; старое содержимое остаётся целым при ошибке валидации. Проверить в серверных тестах `groups.test.ts`.
2. Обновление шаблона не должно менять ID/автора создания и ранее сформированные группы события; запись `group_template_updated` должна содержать редактора и название. Проверить в `groups.test.ts`.
3. Совместимость старого клиента: `group-templates/list` и старый вызов `group-templates/save` продолжают работать без изменений. Проверить контракт и вызовы в `http.test.ts` и `groups.test.ts`.
4. Поиск вместе с одним классом должен находить совпадения на следующих страницах, исключая уже назначенных людей; переход по фильтру сбрасывает старые страницы. Проверить компонентно и e2e на составе больше одной страницы.
5. 51-й участник не добавляется через интерфейс и не сохраняется при прямом API вызове; пустой поиск/фильтр остаётся понятным. Проверить компонентно и в `groups.test.ts`.
6. Диалог не должен обрезать действия или создавать горизонтальную прокрутку на 375 и 1240 px. Проверить e2e на узком и широком окне.
