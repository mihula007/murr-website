## Матрица ролей (пункт 2)

Сверка кода с [01-roles.md](../../requirements/01-roles.md): каждая операция
сервисов `_shared/*/service.ts` проверена по набору ролей в `requireRole`.
Расхождений нет:

- кандидат — только своя заявка (`applications/resubmit`), уведомления и
  кабинет; чтец — только кабинет и профиль (уведомления закрыты);
- член — события, голосования, публикации (чтение), рынок (свои), обсуждения,
  рейтинг, состав; офицер — плюс управление событиями (свои, постоянные —
  любые, Q-47), группы, голосования, заявки, публикации (свои), учёт и Excel,
  рассылки, восстановление чтеца; администратор — всё, включая аккаунты,
  журнал, удаление;
- владение («свои») проверяют `canManageEvent`, `canManagePublication`,
  `canManageListing` после проверки роли.

Тесты: запрет гостю — для всех закрытых маршрутов по HTTP
(`tests/server/http.test.ts`); запреты другим ролям — в тестах каждого
модуля (`forbidden`), но не полным перебором «операция × роль». Data API и
Storage закрыты для браузерных ролей (pgTAP и HTTP-тесты).

## Ошибки и сбои (пункт 3)

| Случай                        | Покрытие                                                                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Обрыв регистрации             | E2E «прерванная регистрация продолжается после входа»; черновик во вкладке без пароля                                                                                 |
| Повтор и гонки                | Решение по заявке — `state_conflict`; голос против закрытия — блокировка; Cron и кнопка без дублей; два аккаунта на один Telegram; черновики под параллельной записью |
| Две вкладки                   | E2E «вторая вкладка не подаёт повторно»; завершение регистрации идемпотентно параллельно                                                                              |
| Закрытие события              | Одна транзакция; повтор и изменения закрытого — `state_conflict`                                                                                                      |
| Сбой удаления                 | Сбой Storage, откат БД, сбой Auth — повтор продолжает с места сбоя без второго аудита                                                                                 |
| Повторное нажатие             | `ConfirmActionDialog` блокирует кнопки на время запроса                                                                                                               |
| Отзыв доступа во время работы | Ответ `forbidden` перечитывает профиль (клиентский тест); смена роли и блокировка сразу закрывают доступ на сервере                                                   |
| Смена пользователя            | Кеш TanStack Query очищается (клиентский тест)                                                                                                                        |
| Истёкшая или чужая сессия     | Сервер считает мусорный токен отсутствием сессии; браузерного сценария истечения нет                                                                                  |
| Обрыв сети в браузере         | Отдельных браузерных сценариев нет; ошибка запроса показывается как отсутствие связи (клиентский тест)                                                                |

## Известные ограничения

- **HTTPS** — до выпуска сертификата пароли идут без шифрования; новых
  участников не приглашать до Enforce HTTPS.
- **Квоты Free:** главный риск — 500 тыс. вызовов функции в месяц при опросе
  шапки раз в 60 с; пауза проекта после недели без активности; копий нет,
  журналы — 1 день. Подробно — [квоты](../../operations/supabase-free-limits.md).
- **Письма:** Resend Free — 100 в день, 3000 в месяц; Auth — 30 в час.
- **Адреса** с `/#/` (hash history); чистые URL не поддерживаются.
- **Обновления опросом** (Q-58, Q-66), без Realtime.
- **Боты:** только Telegram; ВКонтакте и MAX не подключены (Q-86);
  вложения рассылок отменены (Q-82). Один бот — рабочий, тестового нет:
  `npm run telegram:dev` не запускать.
- **Доступ к API** — домен `*.supabase.co`; собственный домен API платный.
  При будущей блокировке нужен бесплатный прокси (решение владельца).
- **Журнал аудита** хранит последние 1000 записей.
- **Время** событий — фиксированное МСК (UTC+3).
- **Резервное копирование** вручную; процедура восстановления не проверялась.
