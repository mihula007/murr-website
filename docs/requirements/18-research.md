# Журнал исследования прототипа

Дата: 08.11.2026, часовой пояс обсуждения Europe/Moscow. Исследован локальный `prototype/index.html`, предоставленный владельцем. Состояние нового React-приложения не менялось.

## Методика

- Прототип обслуживался локально по `http://127.0.0.1:5174/` установленным Vite, без изменения файлов прототипа и без подключения сервера данных.
- Основной инструмент навигации и управления — встроенный браузер Codex. Проверки проводились администратором; дополнительно вошли существующим тестовым офицером и новым тестовым аккаунтом в состояниях кандидат → член → чтец.
- Дополнительное чтение `prototype/index.html` использовано для ограничений полей, охранных проверок, переходов состояний и малодоступных ветвей. README использовался как вторичный источник и сопоставлялся с UI/кодом.
- Авторизация использовала локальные демоданные; пароли и хеши не скопированы в документацию. Реальные пользователи/внешние сервисы не уведомлялись.
- Визуальное направление исследовалось только как контекст расположения действий, не утверждалось как дизайн нового сайта.

## Полностью пройденный путь вступления

Гость → регистрация с аватаром → кандидат без внутреннего доступа → заполнение анкеты → очередь офицера → передача на связанное голосование → голос офицера → завершение → окончательное принятие администратором → повторный вход участником → внутреннее меню и уведомление. Впоследствии администратор назначил этому тестовому аккаунту чтеца; повторный вход показал ограниченную главную и отсутствие внутренних меню.

Это подтверждает положительный путь, а не все комбинации ошибок, конкурентных решений и отказов. Сквозные сценарии README включают и будущую приёмку ещё не проверенных ветвей.

## Особенности инструмента и результаты

1. `window.confirm` временно блокировал команды браузера при завершении голосования. Вкладка восстановилась, завершённое голосование визуально найдено в истории. При завершении тестового ивента использовалось нативное подтверждение; архив и запись учёта проверены после него. Это не доказательство дефекта бизнес-логики.
2. Первые попытки перетаскивания из списка не изменяли группу. При захвате строки за иконку класса перенос сработал: свободный список опустел, группа получила участника, затем лидера. Поэтому drag-and-drop не объявлен неработающим.
3. Прототип позволяет завершить событие с будущей датой. В аналитике оно появилось с датой закрытия, отличной от запланированной. Это наблюдение Q-09/Q-19, не согласованное правило рабочего сайта.
4. Требования не являются заключением о безопасности, полной готовности прототипа или прохождении его автоматических тестов.

## Изменения локального состояния

В отдельном браузерном хранилище проверки остались тестовый аккаунт (в конце — чтец), анкета/её завершённое голосование, обычное тестовое голосование, публикация, объявление, сообщение/реакция, группа с администратором-лидером, шаблон группы, шаблон события, архивное тестовое событие и черновик/шаблон рассылки. У существующего деморейда сохранён ответ администратора «Приду» и его назначение в тестовую группу. На диск скачан тестовый Excel.

Исходники/ресурсы `prototype/` не редактировались. В конце браузер оставлен администратором на составе групп. Автоматическая массовая очистка не выполнялась, чтобы не удалять данные владельца и сохранить возможность повторной проверки.

Осмотрены все доступные из актуального меню разделы и основные диалоги, а скрытые остатки отдельно перечислены.
