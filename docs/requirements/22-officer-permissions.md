# Индивидуальные права офицеров

Страница «Мастерка» позволяет Мастеру или Администратору выбирать офицера и настраивать отдельные полномочия. Права участника клана остаются базовыми для офицера; Мастер и Администратор этими переключателями не ограничиваются.

## Каталог прав

Каждая строка — отдельный переключатель. Персональные права действуют только для учётных записей с ролью `officer`.

| Код | Подпись | Область действия |
| --- | --- | --- |
| `applications.review` | Разбирать новые заявки | Просмотр и разбор очереди новых заявок |
| `applications.submit_vote` | Передавать заявку на голосование | Создать связанное с заявкой голосование |
| `applications.decide_after_vote` | Принимать решение после голосования | Принять или отклонить заявку при завершении связанного голосования |
| `applications.decide_direct` | Принимать решение без голосования | Принять или отклонить новую заявку напрямую |
| `broadcasts.send` | Создавать и отправлять рассылки | Подготовка, черновики и отправка в подключённые каналы |
| `broadcasts.templates` | Управлять общими шаблонами рассылок | Создание и удаление шаблонов; применение при создании рассылки требует `broadcasts.send` |
| `broadcasts.subscriptions` | Просматривать подписки | Просмотр вкладки привязок мессенджеров, без изменения привязок |
| `events.manage` | Создавать и редактировать ивенты | Создание и редактирование с сохранением текущих правил авторства |
| `events.templates` | Управлять шаблонами ивентов | Создание и удаление; применение при создании ивента требует `events.manage` |
| `events.delete_own` | Удалять свои незакрытые ивенты | Удаление доступно только в пределах текущих правил авторства; закрытые события удалить нельзя |
| `groups.manage` | Создавать группы и распределять участников | Создание и изменение групп и состава в активных ивентах |
| `groups.templates` | Управлять шаблонами групп | Создание и удаление шаблонов; применение к ивенту требует `groups.manage` |
| `events.close` | Закрывать ивенты и фиксировать посещаемость | Завершение активного ивента и запись итогов посещения по действующим правилам |
| `votes.manage` | Создавать и редактировать голосования | Создание и редактирование активных голосований |
| `votes.complete_delete` | Завершать и удалять голосования | Завершение и удаление активных голосований; решение по связанной заявке — только по отдельному праву выше |
| `roster.reader_roles` | Присваивать роль чтеца и возвращать чтеца в члены клана | Только член → чтец и чтец → член; остальные смены ролей не входят |
| `activity.view_export` | Просматривать учёт активности, сводки и выгружать Excel | Просмотр истории и аналитики и скачивание отчёта |
| `publications.manage_own` | Управлять своими публикациями | Создание, редактирование, публикация, снятие с публикации и удаление только собственных материалов |

## Требования

- `OFP-01` В категории «Управление» есть раздел «Мастерка». Его видят и открывают только Мастер и Администратор. Они выбирают аккаунт с ролью «Офицер» и видят каталог из этой страницы; нельзя настраивать аккаунт с другой ролью.
- `OFP-02` У каждого офицера все перечисленные права изначально выключены, в том числе у уже существующих офицеров при первом выпуске. Мастер или Администратор включает только необходимые права.
- `OFP-03` Права применяются только к офицерам. Членские возможности офицера не меняются: например, он продолжает видеть ивенты, отвечать на них, участвовать во внутренних обсуждениях и создавать/вести собственные объявления рынка. Управление чужими объявлениями рынка остаётся только у Администратора. Текущие полные права Мастера и Администратора не подчиняются переключателям.
- `OFP-04` Переключатели сгруппированы по смыслу и имеют подписи из каталога. На компьютере переключатель стоит напротив названия; на телефоне список читается без горизонтальной прокрутки.
- `OFP-05` Изменения не сохраняются по одному переключателю. Кнопка «Сохранить» атомарно применяет все изменения для выбранного офицера; дополнительное подтверждение не требуется. Ошибка сохранения не выдаётся за успех и не меняет сохранённые права. Если ни одно значение не изменилось, лишняя запись аудита не создаётся.
- `OFP-06` Каждое реально включённое или выключенное право записывается в журнал Администратора с исполнителем, офицером-целью, названием права и новым состоянием. Автоматический сброс при смене роли также отражается в журнале. Категория журнала — «Права офицеров». Уведомление офицеру не отправляется.
- `OFP-07` После сохранения меню офицера скрывает разделы управления, для которых у него нет соответствующего права. Доступные члену клана разделы остаются видимы; отсутствие права управления скрывает только управление, а не базовое чтение или действие члена.
- `OFP-08` Сервер проверяет персональное право при каждом защищённом действии. Скрытая кнопка или пункт меню сами по себе не являются защитой; прямой вызов запрещённой операции отклоняется.
- `OFP-09` Если аккаунт перестаёт быть офицером, все его персональные права очищаются. При последующем назначении офицером все права выключены. Мастер и Администратор не изменяют собственные возможности через этот каталог.
- `OFP-10` Форма предупреждает об уходе со страницы с несохранёнными изменениями согласно общему правилу GEN-01. Переключение выбранного офицера при несохранённой форме не теряет значения без предупреждения.

## Приёмка

1. Мастер и Администратор открывают «Мастерку»; другие роли не видят раздел и не могут получить его данные прямым запросом.
2. Для каждого офицера начальное состояние — все переключатели выключены. Для аккаунтов других ролей экран настройки недоступен.
3. Изменить несколько прав, сохранить и открыть настройки снова: новые состояния сохранены; в журнале есть запись по каждому изменённому праву с правильным исполнителем, целью и состоянием; офицеру уведомление не пришло.
4. Включить право и проверить действие; затем выключить, сохранить и проверить, что кнопка/раздел скрыты, а прямой вызов соответствующей операции запрещён. Проверить отдельно каждую строку каталога и её границы из описания.
5. У офицера без дополнительных прав проверить обычные возможности члена клана, включая просмотр/ответ на ивент и собственное объявление рынка.
6. Мастер и Администратор сохраняют прежние полномочия; Администратор остаётся единственным, кто управляет чужими объявлениями рынка.
7. Перевести офицера в другую роль: права очищены; назначить офицером снова — все права выключены.
8. Проверить предупреждение при уходе с несохранёнными изменениями, ошибку сохранения, кнопку «Сохранить» без лишнего подтверждения, группировку и ширину экрана телефона.
