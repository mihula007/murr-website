# Личные уведомления и новые записи разделов

Источники: UI уведомления о приёме, прочтения и счётчиков меню; код `notifyUser`, `renderNotificationBell`, `openUserNotification`, `markAllNotificationsRead`, `newSectionRecordIds`, `unseenSectionCount`, `markNewSectionVisited`.

## Личная история

- `NTF-01` Колокольчик виден вошедшему аккаунту с разрешёнными личными уведомлениями; чтецу он недоступен согласно ACL-06 и HOM-10. Истории и состояние прочтения разделены по аккаунтам; вход в другой аккаунт не показывает чужую историю.
- `NTF-02` Уведомление содержит заголовок, краткий контекст и дату/время. Непрочитанные выделены; значок показывает их число, свыше 99 — «99+» (Код).
- `NTF-03` Источники: упоминание/ответ в обсуждении; добавление в группу; назначение пати-лидером; ответ на событие для автора события; изменение роли; прямой/окончательный приём или отказ по заявке.
- `NTF-04` Действие пользователя над самим собой не создаёт ему уведомление. При ответе с упоминанием того же адресата код исключает повтор одного получателя в рамках сообщения.
- `NTF-05` Открытие панели без выбора записи не должно автоматически прочитывать всё. Нажатие записи отмечает её прочитанной; «Прочитать все» отмечает текущую личную историю, сохраняя её.
- `NTF-06` Нажатие открывает связанный объект и разрешённый контекст. После подачи заявки пользователь перенаправляется на главную.
- `NTF-07` Пустая история имеет понятное состояние. Недоступный/удалённый родитель не должен давать доступ к закрытым данным; поведение перехода необходимо уточнить отдельно.
- `NTF-08` История личных уведомлений хранится на сервере; ограничение в 500 записей из прототипа не является требованием к новой версии.

- `NTF-13` При удалении пользователя связанные с ним уведомления удаляются; технические детали обработки уведомлений других получателей уточняются при проектировании.

## Индикаторы новых объектов

- `NTF-09` Новые записи считаются отдельно для разделов ивентов, голосований, публикаций, рынка, заявок и аккаунтов, где они доступны роли.
- `NTF-10` Красный счётчик означает объекты, появившиеся с последнего просмотра раздела, а не непрочитанные сообщения или количество незавершённых заявок вообще.
- `NTF-11` Отметки просмотра персональны для каждого аккаунта; открытие раздела сбрасывает соответствующую новизну, не чужие отметки.
- `NTF-12` Код отдельно учитывает собственные новые объекты и начальную инициализацию просмотра. Точная семантика первой сессии/редактирования старой записи требует отдельного уточнения.

## Приёмка

1. Администратор принимает кандидата: у кандидата появляется одно личное уведомление, у администратора — нет копии самому себе.
2. Прочитать одну запись: число уменьшается на один; «Прочитать все» обнуляет только непрочитанные текущего аккаунта.
3. Создать событие под одним аккаунтом, открыть меню под другим: счётчик новых объектов отделён от колокольчика и снимается посещением раздела.
4. Проверить ссылки на ивент, голосование, публикацию, заявку и удалённый объект после решения Q-21.

Внешние push, почтовая доставка и отправка ботами этой историей не реализуются; см. BRC.
