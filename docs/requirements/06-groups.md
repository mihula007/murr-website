# Участники, пати и шаблоны групп

Роли: внутренние роли читают; офицер/админ формируют группы актуального события. Пати-лидер — участник конкретной группы, а не роль сайта.

Источники: UI диалога события, успешный drag-and-drop участника, назначение лидера и сохранение шаблона; код `getEventPeople`, `renderEventGroups`, `dropIntoEventGroup`, `dropIntoAttendeePool`, `setEventGroupLeader`, `copyEventGroupNames`, `saveGroupTemplate`, `applyGroupTemplate`.

## Состав блока

- Боковой список участников с вкладками «Придут», «Не придут», «50/50», «Не отметились», числами и поиском по нику/классу.
- Центральная область групп: создание по названию, состав, порядок, переименование, выбор лидера, копирование ников, переход к рассылке и удаление группы.
- Соседний чат события — DSC. Его сообщения не являются составом группы.

## Требования

- `GRP-01` Свободные участники распределены по ответам; у строки видны ник, класс и иконка класса. Назначенные в группу исключаются из свободного списка. Числа вкладок в диалоге могут отличаться от общего числа ответов в карточке именно по этой причине.
- `GRP-02` Поиск ограничивает отображаемый пул по нику или классу, не удаляя ответы и назначения.
- `GRP-03` Офицер/админ создаёт именованную группу. Пустое имя отклоняется (Код). У группы показывается число участников.
- `GRP-04` Человек переносится из бокового списка в центральную группу drag-and-drop; успешный перенос одновременно убирает его из свободного пула и добавляет в состав. В исследовании перенос подтвердился при захвате строки за иконку класса.
- `GRP-05` Допускается ручное добавление из любой категории ответа, включая не отметившихся. Назначение в группу не меняет само решение участника.
- `GRP-06` Один участник не должен одновременно находиться в нескольких группах одного события. Перенос между группами меняет назначение, перенос обратно в пул снимает его (Код).
- `GRP-07` Порядок внутри группы изменяется перетаскиванием за маркер; порядок сохраняется, отображается нумерация (Код, UI маркера).
- `GRP-08` Лидер выбирается из участников этой группы либо «Без лидера». У выбранного участника видна подпись «— Пати лидер». Удаление/перенос лидера не должно оставлять ссылку на человека вне группы (Код).
- `GRP-09` Название группы меняется отдельным действием с карандашом. Удаление группы возвращает людей в пул и не удаляет аккаунты/ответы (Код).
- `GRP-10` «Скопировать ники» копирует ники состава в порядке группы через запятую и показывает успех либо ошибку. Пустая группа даёт сообщение без ложного копирования (Код).
- `GRP-11` «Рассылка» группы формирует список участников с отметкой пати-лидера. Для пустой группы подготовка не выполняется; внешние адресаты в прототипе реально не определяются (BRC).
- `GRP-12` Библиотека шаблонов открывается из расписания и диалога события. Максимум 20 шаблонов; отображается занятое количество.
- `GRP-13` Конструктор шаблона содержит полный текущий состав клана, поиск, именованные группы, их порядок и лидеров; для сохранения нужны название шаблона и минимум одна группа (Код).
- `GRP-14` «Сохранить как шаблон» в событии переносит текущий состав в конструктор. Шаблон сохраняет группы, последовательность участников и лидеров; не является ссылкой на изменяемый состав события.
- `GRP-15` При применении шаблон заменяет текущее распределение. Если группы уже есть, требуется подтверждение. Автоматически включаются только люди с ответом «Приду»; остальные остаются для ручного добавления. Лидер назначается только если он попал в состав (Код).
- `GRP-16` Для завершённого события состав читается, но создавать/менять группы, порядок, лидера и применять шаблон нельзя. Архивирование фиксирует данные для ACT.
- `GRP-17` Добавление в группу и назначение лидером может создавать личные уведомления; собственные действия над собой уведомлений не создают (Код, NTF).

- `GRP-18` При удалении пользователя его назначения в группах удаляются, а ссылка на него как лидера очищается. Исторические отметки посещения удаляются согласно ACT-17; переход в чтецы не удаляет исторические записи.

## Приёмка

1. Из вкладки «Придут» перенести участника в группу: число группы +1, свободный список больше его не содержит, ответ «Приду» сохранён.
2. Перенести того же человека в другую группу и обратно в пул; проверить отсутствие дубликатов. Повторить из вкладки «Не отметились».
3. Назначить лидера, переместить/удалить его: у группы нет некорректного лидера; порядок остальных сохранён.
4. Сохранить группу как шаблон; применить к другому событию, где один человек ответил «Приду», другой «50/50»: второй автоматически не включается.
5. Закрыть событие, открыть состав: назначения читаются, все управляющие операции запрещены.
