# Участники, пати и шаблоны групп

Роли: внутренние роли читают; офицер/админ формируют группы актуального события. Пати-лидер — участник конкретной группы, а не роль сайта.

Источники: UI страницы события, успешный drag-and-drop участника, назначение лидера и сохранение шаблона; код `getEventPeople`, `renderEventGroups`, `dropIntoEventGroup`, `dropIntoAttendeePool`, `setEventGroupLeader`, `copyEventGroupNames`, `saveGroupTemplate`, `applyGroupTemplate`.

## Состав блока

- Слева расположен свободный список участников с вкладками «Придут», «Не придут», «50/50», «Не отметились», числами, поиском по нику и отдельным фильтром по классу.
- Справа расположена доска групп. На широком экране карточки раскладываются сеткой и переходят на следующую строку, когда не помещаются; длинный список групп прокручивается внутри колонки. На узком экране карточки идут столбцом в потоке страницы. В карточке доступны создание и удаление группы, состав, порядок, переименование, выбор лидера, копирование ников и переход к рассылке.
- Чат события открывается отдельным окном по кнопке «Обсуждение ивента» в шапке страницы и не занимает место в блоке участников и групп (DSC-01).

## Требования

- `GRP-01` Свободные участники распределены по ответам; в строке видны только ник, иконка класса и характеристики ПА, ПЗ, БУ, ХП и БД из сохранённого профиля (пустые значения — тире). Название класса и ответ рядом с ником не дублируются. Заголовки характеристик сортируют список: первое нажатие — по убыванию, каждое следующее переключает направление; пустые значения остаются внизу. Доступны поиск по нику и отдельный фильтр по классу. На широком экране список участников прокручивается внутри своей колонки, пока группы остаются рядом; список групп при необходимости тоже прокручивается внутри колонки. Назначенные в группу исключаются из свободного списка. Числа вкладок на странице события могут отличаться от общего числа ответов в карточке именно по этой причине. В закрытом событии снимок посещения не содержит характеристик, поэтому их столбцы и сортировка не показываются.
- `GRP-02` Поиск по нику и отдельный фильтр по классу ограничивают отображаемый пул, не меняя ответы и назначения.
- `GRP-03` Офицер/админ создаёт именованную группу. Кнопки создания и шаблонов стоят сразу после заголовка «Группы» и счётчика групп. Пустое имя отклоняется (Код). У группы показывается число участников.
- `GRP-04` Человек переносится из левого списка в карточку группы перетаскиванием; успешный перенос одновременно убирает его из свободного пула и добавляет в состав. Карточки занимают доступные места в строке и переходят на следующую строку, когда не помещаются. Перенос обратно в список снимает назначение. В свободном списке и группах показывается иконка класса без подписи названия. Под курсором показывается компактная карточка участника целиком.
- `GRP-05` Допускается ручное добавление из любой категории ответа, включая не отметившихся. Назначение в группу не меняет само решение участника.
- `GRP-06` Один участник не должен одновременно находиться в нескольких группах одного события. Перенос между группами меняет назначение, перенос обратно в пул снимает его (Код).
- `GRP-07` Порядок внутри группы изменяется перетаскиванием за маркер; порядок сохраняется, отображается нумерация (Код, UI маркера).
- `GRP-08` Лидер выбирается из участников этой группы либо «Без лидера». У выбранного участника видна компактная подпись «— ПЛ» (с полным пояснением «Пати лидер» для доступности). Удаление/перенос лидера не должно оставлять ссылку на человека вне группы (Код).
- `GRP-09` Название группы меняется отдельным действием с карандашом. Удаление группы возвращает людей в пул и не удаляет аккаунты/ответы (Код).
- `GRP-10` «Скопировать ники» копирует ники состава в порядке группы через запятую и показывает успех либо ошибку. Пустая группа даёт сообщение без ложного копирования (Код).
- `GRP-11` В карточке группы доступны компактные элементы выбора лидера, копирования ников, подготовки рассылки и удаления. «Рассылка» группы формирует список участников с отметкой пати-лидера. Для пустой группы подготовка не выполняется; внешние адресаты в прототипе реально не определяются (BRC).
- `GRP-12` Библиотека шаблонов открывается из расписания и со страницы события. Максимум 20 шаблонов; отображается занятое количество.
- `GRP-13` Конструктор шаблона содержит полный текущий состав клана, поиск, именованные группы, их порядок и лидеров; для сохранения нужны название шаблона и минимум одна группа (Код).
- `GRP-14` «Сохранить как шаблон» в событии переносит текущий состав в конструктор. Шаблон сохраняет группы, последовательность участников и лидеров; не является ссылкой на изменяемый состав события.
- `GRP-15` При применении шаблон заменяет текущее распределение. Если группы уже есть, требуется подтверждение. Автоматически включаются только люди с ответом «Приду»; остальные остаются для ручного добавления. Лидер назначается только если он попал в состав (Код).
- `GRP-16` Для завершённого события состав читается, но создавать/менять группы, порядок, лидера и применять шаблон нельзя. Архивирование фиксирует данные для ACT.
- `GRP-17` Добавление в группу и назначение лидером может создавать личные уведомления; собственные действия над собой уведомлений не создают (Код, NTF).

- `GRP-18` При удалении пользователя его назначения в группах удаляются, а ссылка на него как лидера очищается. Исторические отметки посещения удаляются согласно ACT-17; переход в чтецы не удаляет исторические записи.
- `GRP-19` Член клана видит на актуальном и завершённом событии только группу, в которую назначен сам; остальные группы и свободный список участников ему недоступны. Если группы нет, вместо списков показывается «Вы пока не распределены по группе». Офицер и администратор видят полную расстановку и участников. Ограничение просмотра не меняет ответы, группы или архивные данные и обеспечивается при выдаче данных сервером.

## Приёмка

1. Из вкладки «Придут» перенести участника в группу: число группы +1, свободный список больше его не содержит, ответ «Приду» сохранён.
2. Перенести того же человека в другую группу и обратно в пул; проверить отсутствие дубликатов. Повторить из вкладки «Не отметились».
3. Назначить лидера, переместить/удалить его: у группы нет некорректного лидера; порядок остальных сохранён.
4. Сохранить группу как шаблон; применить к другому событию, где один человек ответил «Приду», другой «50/50»: второй автоматически не включается.
5. Закрыть событие, открыть состав: назначения читаются, все управляющие операции запрещены.

Доказательство UI: [состав с назначенным лидером](evidence/event-groups-admin.jpg). Полный набор переносов и применение шаблона не тестировались исчерпывающе; см. журнал исследования.
